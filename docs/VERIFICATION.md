[Релизная сборка 0.6.0](https://github.com/Georgy-hook/GeoRoute/actions/runs/46158670020) прошла Windows-тесты клиента, установку, запуск, обновление и удаление. [Точные файлы, SHA-256 и покрытие VirusTotal](security/v0.6.0.md). Тесты сценариев главного экрана используют изолированные сетевые ответы; они не подменяют браузерную проверку.

**Практическая проверка 28.11.2026.** Тот же MSI установлен на физической Windows. Выполнено одно отключение и подключение сохранённого профиля штатным обработчиком установленного клиента из раздела «Дополнительно». Результаты относятся к одной сети и одному узлу:

| Этап | Результат |
|---|---|
| WARP выключен, маршрут узла снят | TCP установился; TLS не завершился за 2647 мс. |
| Тот же узел после включения WARP | Первое ожидание закончилось в состоянии повтора. Служба восстановила соединение без второй команды; профиль и точечный маршрут подтверждены. TLS прошёл, HTTPS вернул 302 на проверку Google за 1875 мс. Редирект не является ответом модели. |
| Браузер при восстановленном соединении | После задержки пользователь подтвердил официальный адрес `gemini.google.com`, сеанс со входом и новую правильную реплику на контрольный вопрос. Это ручное наблюдение, не ответ сетевой пробы. |

Пакеты конкретного запроса генерации не трассировались. Этот тест не доказывает причину задержки, доступность всех узлов, загрузку GIF/MP4 или работу после перезагрузки ПК. Историческая [сборка 0.5.0](https://github.com/Georgy-hook/GeoRoute/actions/runs/42494096217) имеет [отдельный отчёт](https://github.com/Georgy-hook/GeoRoute/blob/v0.5.0/docs/security/README.md).

Проверки GitHub Actions охватывают DNS-протокол Bridge, восстановление, профили ChatGPT/Gemini, региональный выбор, запуск GUI и автозапуск.

Тест установщика в одноразовой Windows VM проверяет установку в путь с кириллицей и пробелами, совпадение файлов с ZIP, запуск GUI через команду ярлыка, запрет обновления работающего приложения, сохранение профилей, списка сайтов/выбранного DNS и кеша каталога при обновлении/повторной установке, удаление и очистку своего автозапуска. Установка и удаление не должны менять hosts, DNS или прокси.

Отдельная [проверка опубликованного релиза](../.github/workflows/verify-windows-release.yml) скачивает MSI и ZIP прямо из GitHub Releases, сверяет SHA-256 с GitHub, файлами `.sha256` и отчётом безопасности в теге. Релизные файлы не пересобираются. Дополнительно проверяются стандартная папка `%LOCALAPPDATA%\Programs\GeoRoute`, ярлыки рабочего стола и меню «Пуск», запись в списке установленных приложений и её удаление. Для теста обновления создаётся только временный пакет следующей версии с тем же содержимым; он не публикуется.

**Историческая проверка MSI 0.4.2, 06.11.2026:** [результат проверки точных опубликованных файлов](https://github.com/Georgy-hook/GeoRoute/actions/runs/42213482660).

Текущий снимок [добавления профиля](images/add-profile.png) экспортирован WPF-кодом GeoRoute 0.4.3: в ней одна форма GeoHide для обоих сервисов. Снимки установленной 0.4.2 сохранены в [проверке опубликованной версии](https://github.com/Georgy-hook/GeoRoute/actions/runs/42210022722). Режим экспорта использует чистые настройки и не выполняет сетевых действий; снимки не служат доказательством подключения.

Bridge проверяется через настоящий Windows Service Control Manager под LocalService: запуск, остановка, перезапуск, ошибка запуска и восстановление. Тест не меняет DNS сетевых адаптеров и не выполняется на компьютере пользователя.

Установка Bridge проверяет обычное разрешение имён через DNS Windows. Совпадение правил в кабинете NextDNS с адресами GeoHide оценивается отдельно: ошибка такого правила или ограничение Google не должны откатывать исправный DNS. При тайм-ауте или пустом ответе проверка установки по-прежнему завершается ошибкой.

Успешная проверка сервера в приложении подтверждает ответ на проверочный запрос в этот момент. Она не гарантирует загрузку любого вложения, прохождение авторизации, отсутствие CAPTCHA или работу управления компьютером Dot. Полную перезагрузку компьютера пользователя CI не заменяет.

Для Gemini проверяются HTTPS страницы/API и общая цепочка Google через одно HTTP/2-соединение. TLS проверяет сертификат Gemini; перед запросом Google проверяется, что тот же сертификат покрывает точное имя www.google.com. Проверка привязана к физическому интерфейсу, ограничивает время, размер ответа и число перенаправлений, принимает только два точных Google-имени. Cookie не сохраняются и не копируются из браузера. Страница HTTP 200 подтверждает сетевой маршрут; вход в аккаунт и ответ модели проверяются отдельно. Отдельное TLS-соединение www не требуется для успешно проверенного общего маршрута. Неудачный Google-маршрут не отключает рабочий ChatGPT, но показывается как ограничение Gemini.

HTTP/2 использует закреплённые чистые Python-пакеты h2, hpack и hyperframe из PyPI. Их wheel-файлы с лицензиями включены в пакет; SHA-256 проверяются при запуске и сборке. На компьютере пользователя зависимости не скачиваются. Новые EXE-обёртки не добавляются.

Целостность локальных ссылок, изображений и якорей Markdown проверяет `python tools/check_docs.py`; эта проверка включена в CI. Ссылки старых релизов на инструкции закреплены за соответствующими тегами.

VirusTotal привязан к точным хешам файлов. Смотрите [проверки безопасности](security/README.md); результаты старой версии не распространяются на новый установщик. Отсутствие обнаружений не является гарантией безопасности.

Выборочный DNS проверяется настоящими UDP/TCP-запросами: границы выбранных имён, REFUSED для остальных и проверка HTTPS-сертификатов. Отдельный Windows SCM/NRPT-тест проверяет запуск/перезапуск LocalService и удаление своих правил без изменения DNS адаптеров или hosts. Мониторинг DNS проверяет `example.com`; тесты контроллера покрывают загрузку, дубликаты запусков, чужой run ID, тайм-аут, выбор одного результата в PowerShell 5.1 и устаревание. Обе таблицы проверяются при малом и развёрнутом окне. Новый снимок DNS-мониторинга экспортирован из WPF с публичными результатами реальной локальной проверки 8 ноября 2026 года; он не обещает доступность в других сетях.

## Проверки изменений 0.6.0

Локально без сетевых изменений проверяются сохранение выбранного узла из мониторинга, повторное использование одной карточки, блокировка устаревших/незавершённых результатов, отказ HTTPS вложений и откат при невозможности сохранить каталог. Автоподбор не переписывает выбранный явно адрес. Миграция 0.5 → 0.6 добавляет точный ресурсный домен Gemini, сохраняет IP, проверенный Google-маршрут и пользовательские профили. Реальный worker с подменённым транспортом подтверждает: ошибка `gemini.gstatic.com` отображается отдельно и не отключает работающий ChatGPT.

WPF проверяется на малом и развёрнутом окне, в процессе загрузки и с раскрытыми настройками. Установщик проверяется отдельно в одноразовой Windows CI: установка, обновление, запуск, сохранение пользовательских данных и удаление. Эти проверки не доказывают доступность серверов у конкретного провайдера.

На 22.11.2026 подтверждение реального ответа модели и скачивания вложений при применённом профиле остаётся отдельным ручным сценарием. Точечные запросы не требуют смены действующих VPN/DNS/hosts. Рекомендация добавить `gemini.gstatic.com` реализована; её достаточность для проблемного подключения пока не подтверждена. Статусы мониторинга не следует выдавать за успешный вход в аккаунт или ответ модели.


Дополнительная проверка 22.11.2026: три одинаковых GeoHide-IP чередующимися запросами отвечают через существующее правило Happ, но не через физический интерфейс. Это подтверждает зависимость отказа от пути. Для альтернативного Zapret DNS проверены текущий DoH и US-маршрут ChatGPT/Gemini, включая совместную проверку Google по HTTP/2; 11 имён совместимого профиля и реальный импорт в изолированную копию приложения. [Результаты и ограничения](SMARTDNS-ROUTES.ru.md). Авторизованный ответ модели и конкретная GIF/MP4 этими тестами не проверены.


Регрессия импорта/мониторинга: реальный WPF-тест воспроизвёл серую кнопку на старом коде, когда сканирование завершалось во время импорта. После исправления доступность строки не сохраняет временный глобальный busy-флаг: родительская таблица блокирует действие и автоматически восстанавливает его после операции. Проверены оба порядка завершения, «Никогда» без нового запроса и сохранение блокировки устаревших, удалённых и неисправных узлов. Полный Windows-набор и установщик прошли CI с этим исправлением.
