# Установка GeoRoute

## Обычная установка

1. Откройте [последний релиз](https://github.com/Georgy-hook/GeoRoute/releases/latest).
2. Скачайте **GeoRoute-Setup-0.4.2-x64.msi**. **Source code** и ZIP не нужны.
3. Откройте файл → **Далее → Установить**.
4. Завершите установку и откройте ярлык **GeoRoute** на рабочем столе либо в меню **Пуск**.
5. Дождитесь проверки серверов, выберите доступный профиль в **Серверы**, нажмите **Включить** на главной и подтвердите запрос Windows.

Установка выполняется для вашей учётной записи и сама не меняет сеть. Администратор нужен для подключения. Python, Java, аккаунт NextDNS и GitHub настраивать не требуется. Нужны Windows 10/11 x64, Windows PowerShell 5.1 и .NET Framework 4.8.

Папка приложения: `%LOCALAPPDATA%\Programs\GeoRoute`. Установщик пока без цифровой подписи издателя: Windows может предупредить о неизвестном приложении. Загружайте официальный релиз, сверяйте SHA-256 и [отчёт безопасности](security/README.md). VirusTotal не заменяет цифровую подпись и репутацию SmartScreen.

## Обновление

Выберите **Выход** на значке GeoRoute в трее, затем запустите новый Setup. Папка будет найдена автоматически. Профили, адреса, настройки, журналы и резервные копии сохраняются. Закрытие окна может только свернуть приложение в трей.

## Переход с ZIP

ZIP и установленное приложение используют разные папки настроек. Перед переходом нажмите **Выключить** в старой версии, отключите её запуск с Windows и выберите **Выход** в трее. Дополнительные режимы Bridge/US-прокси тоже отключите, если включали их. Затем установите MSI и добавьте свои `.hosts` через **Серверы → Добавить сервер → Из файла**. Автоматического переноса нет; сохраните старую папку до переноса нужных профилей.

## Без установки

Скачайте дополнительный **GeoRoute-Windows-x64-0.4.2.zip**, правой кнопкой → **Извлечь всё**, затем откройте **GeoRoute.cmd**. Это тот же GUI. Сохраняйте всю папку; запуск из архива и перенос одного файла не поддерживаются.

## Удаление

1. Нажмите **Выключить** в приложении. Если включали Bridge или US-прокси, отключите их отдельно в настройках.
2. Выберите **Выход** в трее.
3. Откройте **Параметры Windows → Приложения → GeoRoute → Удалить**. Для ZIP-версии удалите её папку.

Установщик не отключает сеть самостоятельно. Если маршрут остался в hosts, удаление остановится с инструкцией. Личные профили и журналы остаются в папке приложения; их можно удалить после удаления приложения. Автозапуск удаляется только при точном совпадении с этой установленной копией.

## Статусы

В разделе **Серверы** выберите общий профиль **GeoHide — основной**, запасной, US или RU. В каждом включены ChatGPT, Gemini и вложения. Смешанный **US + EU — ChatGPT + Gemini** отправляет Gemini и файлы через EU и требует рабочих US/EU для ChatGPT и вложений. Ограничения Gemini показаны отдельно и не отключают рабочий ChatGPT.

Если Google просит CAPTCHA, откройте Gemini в браузере и пройдите её самостоятельно. Зелёная сетевая проверка означает доступность HTTPS страницы и API; она не подтверждает вход в аккаунт и ответ модели. Сервер может работать у одного провайдера и быть недоступным у другого — ориентируйтесь на свежую проверку в **Мониторинге**.

- **Выключено** — подключение отсутствует; это нормально.
- **Проверяю серверы** — свежего результата ещё нет.
- **Включено** — применены адреса, необходимые узлы прошли проверку.
- **Подключено · Gemini ограничен** — ChatGPT доступен, но проверка Gemini выявила ограничение. Подробности указаны на главном экране и в мониторинге.
- **Сервер недоступен** — выберите другой в разделе **Серверы**.

Не работают GIF, видео или ZIP — откройте **Помощь**. Очистка DNS-кеша обновляет сохранённые адреса, но не восстанавливает недоступный сервер. [Добавление профиля](../README.md#как-добавить-собственный-профиль) · [Что проверяется](VERIFICATION.md).

## Если Google показывает два разных IP

Страница «подозрительный трафик» с `IP₁ ≠ IP₂` и без поля CAPTCHA означает, что проверка сейчас недоступна. Один из возможных источников — разные маршруты `gemini.google.com` и `www.google.com`. Владелец GeoHide описывал это в [обсуждении 17 октября](https://t.me/Inter_net_Helper/27606) и [28 октября](https://t.me/Inter_net_Helper/29424).

Оба имени должны открываться через один сервер. GeoRoute проверяет также общую цепочку HTTP/2: Gemini → проверка Google → Gemini, с обычной проверкой сертификата для обоих имён и временными cookie только в памяти проверки. Рабочая цепочка учитывается даже тогда, когда отдельное новое TLS-соединение к `www.google.com` не открывается. Подтверждённый маршрут добавляет оба имени на один IP в основной, запасной и смешанный профили.

В Chrome/Chromium после запуска сначала откройте Gemini. Этот режим использует общее соединение; холодный запуск Google Поиска первым может не работать на узле без отдельного HTTPS для `www.google.com`. Маршрут затрагивает также Google Поиск. Gmail и вход в аккаунт отдельными правилами не перенаправляются. При смене узла может потребоваться перезапуск браузера, чтобы закрыть старые соединения.

Выберите другой доступный сервер и примените профиль. Если на всех узлах проверка Google недоступна, добавление строки или очистка кеша сами по себе не устраняют причину: нужно проверить поддержку домена на узле и фильтрацию у провайдера. Google также может временно ограничивать общий адрес прокси — [пояснение Google](https://support.google.com/websearch/answer/86640). Если поле CAPTCHA появилось, пройдите проверку самостоятельно.

Включённый VPN/TUN может перехватывать системные запросы даже с IP из hosts. Мониторинг GeoHide специально использует физический интерфейс; ответ обычного curl или открытая страница с HTTP 200 не доказывают работу выбранного GeoHide-узла и ответа модели.
