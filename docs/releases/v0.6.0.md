# GeoRoute 0.6.0 — прямое подключение и необязательный WARP

Кандидат с новым главным экраном готовится к проверке. Опубликованная версия пока [0.5.0](https://github.com/Georgy-hook/GeoRoute/releases/tag/v0.5.0). Пакеты кандидата от 22 ноября заменены; их отчёт VirusTotal не применим к новым файлам.

## Задачи и изменения

- [x] Прочитать сообщения о неполадках и рекомендации, сверить с публичными источниками GeoHide. Частная переписка и персональные данные не публикуются.
- [x] Подключать выбранный проверенный узел прямо из мониторинга, через штатное применение с UAC. Выбор сохраняется в одной карточке; автовыбор не меняет этот адрес.
- [x] Убрать ошибочное закрепление `gemini.gstatic.com` за GeoHide: ресурсы остаются на Google, Gemini и проверка `www.google.com` — на одном узле. Сохранить существующие IP встроенных профилей.
- [x] Учитывать закрытие RU-пула независимо от старого upstream hosts, исключить его из автовыбора. Сохранить пользовательские RU-адреса, которые не входят в закрытый пул.
- [x] Добавить опубликованные EU-кандидаты и альтернативные DNS `dns.geodema.love`, `w.quic.best`. Закрытый RU DNS не опрашивать и не предлагать для подключения.
- [x] Включить настройки интервала автопроверки из develop: от «Никогда» до суток, по умолчанию два часа.
- [x] Проверить профиль, миграцию, ошибки и адаптивный интерфейс локально без изменения сетевых настроек.
- [x] Исправить гонку завершения импорта и мониторинга: готовые узлы доступны сразу после снятия общей блокировки, без повторного сканирования при «Никогда». Реальный WPF-тест проверяет оба порядка завершения и блокировку неисправных строк.
- [x] Проверить новый интерфейс и отказ от установки WARP: от первой кнопки до ответа того же сервера и возврата. Отрисовка и обработчики настоящие; сеть, служба и hosts изолированы. Windows-тесты и установка/обновление/удаление прошли в [PR #30](https://github.com/Georgy-hook/GeoRoute/pull/30).
- [ ] Проверить точные релизные MSI, ZIP и выбранные компоненты на VirusTotal. Сверить размер и SHA-256 каждой выдаваемой загрузки; не пересобирать после проверки. [Аудит кандидата](../security/v0.6.0.md).
- [ ] Отдельно подтвердить ответ модели Gemini, Google, GIF/MP4 и настольный клиент с применённым профилем на проблемном провайдере. Точечные запросы допустимы без смены действующей сети; автоматически VPN не отключать.

## Файлы для проверки кандидата

Для обычной установки нужен `GeoRoute-Setup-0.6.0-x64.msi`. `GeoRoute-Windows-x64-0.6.0.zip` — отдельный переносимый вариант. Проверяйте SHA-256 именно своей загрузки. Установка не подключает профиль и не устанавливает службу WARP.

Обновление: выйдите из GeoRoute через трей → **Выход**, запустите MSI → **Далее → Установить**. Пользовательские настройки сохраняются. Не переключайте работающий VPN ради установки: MSI сам не меняет маршруты, DNS или hosts.

## Найденный резервный маршрут

После первоначальной проверки выполнено сравнение тех же GeoHide-IP напрямую и через уже работающее точечное правило Happ. Три узла ответили через Happ, но не напрямую: отказ зависит от сетевого пути, серверы нельзя считать глобально выключенными.

Дополнительно проверен US-маршрут Zapret DNS `185.4.64.180`: ChatGPT возвращает HTTP 200/US, Gemini — HTTP 200/USA; проверка Google по общей HTTP/2-сессии, API и ресурсы отвечают. В текущем сочетании с выборочным VPN сохраните ChatGPT/Telegram в Happ и используйте [совместимый профиль только для Gemini](../examples/Gemini-with-Happ-US.hosts). [Инструкция, самостоятельный профиль обоих сервисов и границы проверки](../SMARTDNS-ROUTES.ru.md). Профили сохранены отдельно и автоматически не применяются. Пресет DoH в новом установщике обновлён на актуальный адрес.

## Как пользоваться

**Мониторинг → Серверы GeoHide → Проверить серверы → Подключить** в строке нужного узла → подтвердите Windows. Кнопка недоступна во время проверки и при отсутствии свежего успешного результата обязательных проверок. Узел должен поддерживать ChatGPT и вложения; ограничения Gemini показываются отдельно. Выбранный узел появляется в «Серверы», повторный выбор обновляет ту же карточку. Если запрос Windows отменён, профиль сохранён, но подключение не считается изменённым.

Для других DNS: **Мониторинг → DNS-провайдеры → Проверить все DNS → выбрать отвечающий → Настроить этот DNS…**. Добавьте сайты и включите их маршрут отдельной кнопкой. Остальные сайты остаются на прежнем DNS. DNS-IP нельзя без проверки использовать как адрес HTTPS-прокси в hosts.

В **Настройки → Автопроверка серверов** выберите интервал. «Никогда» отключает проверки и при запуске; ручные проверки доступны всегда. Автоподбор обновляет подготовленные профили, а применение в Windows требует явного подключения и UAC.

## Сетевой снимок 22 ноября

В ограниченной проверке из одного подключения ни один из семи EU и четырёх US кандидатов не подтвердил HTTPS Gemini: преимущественно тайм-аут TCP, у одного узла TCP отвечал, но TLS не завершился. Обычный Google frontend при этом вернул HTTP 200. VPN/hosts/DNS не переключались. Это локальный результат с короткими тайм-аутами, а не доказательство глобального закрытия US/EU или точной причины блокировки. Недоступность до TLS не исправляется добавлением домена в hosts.

Два новых альтернативных DoH отвечали на фиксированный тестовый DNS-запрос, однако этого недостаточно для работающего Gemini: один вернул обычные адреса Google, у другого HTTPS по выданному прокси-IP не ответил. Они остаются DNS-кандидатами, не выдаются за проверенные замены HTTPS-узлов GeoHide.

## Что ещё не подтверждено

Общий IP Gemini и `www.google.com` остаётся необходимым для проверки Google. `www.google.com` обслуживает также Google Поиск. Статические ресурсы `gemini.gstatic.com` остаются на Google. Одна правка hosts не снимает блокировку сервера провайдером, репутационное ограничение общего IP или ограничение аккаунта Google. Для всех EU-узлов успешная работа Gemini не заявляется.

Ответы мониторинга относятся к условиям проверки. Включённый VPN/TUN может влиять на результат даже при привязке к физическому IPv4-интерфейсу. После смены сети повторите проверку. HTTPS страницы, API и корня хранилища не доказывает ответ модели или скачивание конкретной GIF.

## Дополнительный режим WARP

Добавлены необязательная служба, управление подключением из настроек и независимый переключатель автоподключения (по умолчанию выключен). Маршруты ограничены точными IP GeoHide, без смены общего DNS и маршрута интернета. Журналы доступны из карточки WARP. Ядро и средство регистрации скачиваются по закреплённым версиям и SHA-256. Подписанная DLL Wintun включена в пакет, чтобы установка не зависела от доступности сайта драйвера. Проверка реального перезапуска Windows остаётся отдельным этапом и не подменяется тестами логики. Подробнее: [WARP](../warp.md).

## Portable и обучение

- На главной есть переход к серверам и встроенная инструкция из четырёх шагов. Она открывается по запросу и не включает сеть сама.
- Уменьшены декоративные элементы, упрощены фоны и карточки настроек. Главное действие и текущее состояние сохранены.
- В ZIP включены Python и библиотеки. WARP остаётся отдельной установкой с правами администратора.
- Сборка принимает отдельную папку вывода, чтобы подготовка portable не заменяла ранее проверенные релизные файлы.

## Проверка службы WARP

В записях от 23 ноября один и тот же узел не завершил TLS напрямую, но ответил по HTTPS через WARP. Отдельный опыт на установленном тогда клиенте подтвердил ответ Gemini в Chrome. Это сопоставление нескольких записей, а не сквозной тест нынешнего MSI. У новой сборки проверяются локальная логика и установка; ответ после входа в аккаунт, получение конкретного медиафайла и перезагрузка Windows остаются отдельными проверками.
