# ChatGPT и Gemini: проверенный резервный маршрут

Проверено 22 ноября 2026 года из одного подключения. Это снимок сетевых проверок, а не обещание постоянной доступности или подтверждение ответа модели после входа в аккаунт.

## Если уже включён Happ для ChatGPT и Telegram

Оставьте работающий Happ. Для Gemini подготовлен [профиль Gemini-with-Happ-US.hosts](examples/Gemini-with-Happ-US.hosts): он содержит только 11 точных имён Gemini и проверки Google. Записей OpenAI и Telegram в нём нет. Совместимость проверена с маршрутом, где эти сервисы идут через VPN, а Gemini — напрямую.

1. Сохраните файл `.hosts` по ссылке выше. Для импорта используйте GeoRoute 0.6.0 или новее: старые версии могут не распознавать `gemini.gstatic.com`.
2. В GeoRoute откройте **Серверы → Добавить сервер → Из файла**. Выберите файл, страну **США**, название **Happ + Gemini — США** и нажмите **Сохранить профиль**. Сохранение не переключает подключение.
3. Когда готовы применить маршрут, выберите новую карточку и нажмите **Включить** на главной. Подтвердите Windows. Это отдельное действие; исследование и импорт не применяют профиль автоматически.
4. Полностью перезапустите браузер, чтобы закрылись старые соединения. Сначала откройте **Gemini**, затем при необходимости проверку Google. Профиль направляет также точный `www.google.com`, который обслуживает Google Поиск, через тот же узел. Общие зоны Google, Gmail и `accounts.google.com` не перенаправляются.

Happ продолжает обслуживать ChatGPT и Telegram. Записей других приложений, игр и системных DNS-серверов этот профиль не меняет. Если VPN направляет через себя также Gemini, условия отличаются от проверенных здесь.

**Для этого режима выбирайте именно файл Gemini-with-Happ-US.hosts.** Подмена OpenAI на адрес российского входа одновременно с зарубежным VPN в тесте привела к ошибке TLS. Провайдер резервного маршрута допускает российские/белорусские подключения и ограничивает зарубежные и хостинговые адреса; результат согласуется с этим ограничением.

## Отдельный профиль для обоих сервисов

[ChatGPT-Gemini-US-ZapretDNS.hosts](examples/ChatGPT-Gemini-US-ZapretDNS.hosts) объединяет ChatGPT, Gemini и известные адреса вложений OpenAI. Сетевые проверки выполнены с прямой привязкой к физическому IPv4-интерфейсу. Этот файл предназначен для самостоятельного DNS/hosts-маршрута; при работающем точечном Happ используйте предыдущий вариант. В ходе диагностики действующий VPN не выключался.

Оба файла используют опубликованный DNS-провайдером вход `185.4.64.180`; это **Zapret DNS**, отдельный от GeoHide оператор. Проверенный выход сервиса — США. Это HTTPS-маршрут, не адрес VPN-сервера и не HTTP-прокси с портом. Файлы являются внешними примерами конфигурации, не частью ранее проверенного установщика.

## Что удалось подтвердить

| Проверка через `185.4.64.180` | Результат |
|---|---|
| ChatGPT, `/cdn-cgi/trace` | HTTP 200, выход US |
| ChatGPT, главная и `/api/auth/providers` | HTTP 200 |
| `auth.openai.com` | HTTPS, HTTP 200 |
| `api.openai.com/v1/models` без ключа | HTTPS, ожидаемый HTTP 401 |
| Gemini, `/app` | HTTP 200, маркер региона USA |
| Проверка Google через общее TLS/HTTP2-соединение Gemini | Успешна, сертификат проверен для обоих имён |
| API Gemini и `gemini.gstatic.com` | HTTPS, ожидаемый HTTP 404 на корне |
| Остальные имена совместимого профиля | HTTPS; алиасы перенаправляются, корни API возвращают 404 |
| Корень хранилища вложений OpenAI | HTTPS, ожидаемый HTTP 404 |
| Импорт обоих файлов в GeoRoute | Успешен, системный hosts не менялся |

Успешный корень хранилища не доказывает скачивание конкретной GIF/MP4, а страница Gemini — ответ модели. Эти действия с авторизованным аккаунтом проверяются отдельно. Прямая TLS-сессия к `www.google.com` на этом узле завершается отказом: проверен именно общий HTTP/2-маршрут после открытия Gemini, как и у ранее проверенных GeoHide-профилей.

## Откуда берётся актуальный адрес

[Состояние провайдера](https://dns.zapret.moe/status.json) публикует текущие входы DoH. На дату проверки работают `https://doh.zapret.moe/dns-query` и опубликованный там публичный вход через Cloudflare. Пресет GeoRoute обновлён с устаревшего `dns.zapret.moe/dns-query` на `doh.zapret.moe/dns-query`; это не включает DNS и не меняет сохранённый активный выбор.

DNS возвращает `185.4.64.180` для Gemini, ChatGPT, ресурсов Gemini и вложений. Для `www.google.com` он возвращает обычные адреса Google: один лишь выбор этого DoH не равнозначен подготовленному профилю с проверкой Google через общий IP.

Адрес входа может меняться. Импортированный `.hosts` фиксирует IP и автоматически не обновляется через DoH. При изменении адреса нужна повторная проверка профиля; отвечающий DNS не доказывает доступность HTTPS-прокси. Не смешивайте DNS-bootstrap IP и адрес, выданный для самого сайта.

Источники: [страница провайдера и ограничения доступа](https://dns.zapret.moe/), [его опубликованное состояние](https://dns.zapret.moe/status.json), [списки GeoHide](https://github.com/Internet-Helper/GeoHideDNS).

## Почему прежний GeoHide не исправился очисткой кеша

Запросы отправлялись непосредственно на опубликованные IP с проверкой сертификатов, без смены DNS, hosts, VPN и маршрутов Windows. Недоступность воспроизводилась ещё до HTTP: преимущественно тайм-аут TCP, на одном EU-узле периодически доступен TCP, но не завершается TLS. На проверенном 8443 рабочий TLS тоже не подтвердился. Разбиение ClientHello на два корректных TLS-record в отдельном тестовом соединении не помогло.

Кеш и список доменов не объясняют такой отказ прямого соединения с IP. Точную сторону потери пакетов — сеть/фильтрация провайдера, промежуточный маршрут или сами серверы — эти проверки не устанавливают. Закрытие RU-пула объявлено владельцем отдельно; на EU/US это объявление не распространяется.
