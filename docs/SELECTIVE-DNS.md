# DNS только для выбранных сайтов

Возможность готовится для GeoRoute 0.5.0. Стабильная 0.4.3 её не содержит.

Окно **Серверы → Сайты и DNS** позволяет выбрать GeoHide EU/US/RU, другой предложенный провайдер или собственный HTTPS DoH. Введите `https://имя/dns-query`; bootstrap IP можно задать вручную. Если поле пустое, имя провайдера ищется через прежний DNS Windows. Пресеты не считаются проверенными до свежего ответа DoH с действительным сертификатом.

Слева доступен [опубликованный GeoHide каталог доменов](https://github.com/Internet-Helper/GeoHideDNS/blob/main/lists/domains.txt). Он обновляется отдельной кнопкой; при ошибке остаётся прежний список. Обновление каталога не включает новые сайты автоматически. Свой домен разрешён вне каталога, но его поддержку должен обеспечить сам DNS-провайдер. Этот каталог не обещает поддержку у альтернативных провайдеров.

## Подобрать отвечающий DNS

Откройте **Мониторинг → DNS-провайдеры**. При первом открытии начинается проверка; повторная — кнопкой **Проверить все DNS**. Таблица показывает очередь/проверку каждого провайдера, ответ, задержку, проверенные bootstrap IP, время и причину отказа. После завершения отвечающие DNS идут первыми, по задержке. Поиск работает по имени и URL.

Проверка отправляет только фиксированный публичный запрос `example.com`, проверяя HTTPS-сертификат, корректность DNS-ответа, RCODE 0 и наличие ответа. Список ваших сайтов другим провайдерам не отправляется. NXDOMAIN и пустой ответ не дают зелёный статус. Это проверка транспорта DoH, а не обещание разблокировки сервисов.

Выберите строку с успешной проверкой не старше пяти минут → **Использовать DNS…**. Откроется окно сайтов с выбранным DNS и проверенными IP; прежний список сайтов сохранится. Ни выбор строки, ни проверка не меняют сеть Windows. **Включить / обновить** в окне сайтов выполняется отдельно. Сохранённый собственный DoH также участвует в общей проверке. При тайм-ауте незавершённые строки получают статус «Не завершено», и кнопку можно нажать снова.

## Пользовательский сценарий

1. Выберите DNS.
2. Найдите сайт и добавьте его в список справа либо вставьте свою ссылку. Путь ссылки убирается, IDN переводится в punycode. До 100 сайтов; дубликаты удаляются.
3. При необходимости включите поддомены. Для составных сервисов добавьте связанные домены из каталога.
4. Проверьте DNS и нажмите **Включить / обновить**. Проверка повторяется перед применением. Windows запросит администратора. Сохранение списка отдельно не меняет подключение.

**Выключить** удаляет только собственные DNS-правила GeoRoute, после чего останавливает и отключает службу. Прежний DNS Windows и hosts не переписываются. Служба и её защищённая папка остаются для повторного включения; при обычном удалении приложения сначала отключите этот дополнительный режим. Установщик не должен оставлять включённые правила без управляющего интерфейса.

## Как это работает

- Windows [NRPT](https://learn.microsoft.com/en-us/powershell/module/dnsclient/add-dnsclientnrptrule) направляет только выбранные пространства имён на `127.0.0.2:53`. У домена отдельное точное правило и, если выбрано, суффиксное правило. Правила других приложений сохраняются; пересечения блокируют применение.
- Отдельная служба `GeoRouteDNS` под LocalService слушает UDP/TCP только на `127.0.0.2`. Внутри она снова проверяет имя запроса. Посторонние имена получают локальный REFUSED и не отправляются провайдеру.
- Запросы выбранных имён передаются одному явно выбранному DoH-провайдеру по HTTPS с проверкой сертификата/имени. Незашифрованного внешнего DNS fallback и скрытой замены провайдера нет. Остальной DNS идёт по прежней системной настройке, включая существующий NextDNS Bridge на `127.0.0.1` / `::1`.
- Изменения адресов того же DoH-имени проверяются каждые пять минут через неизменённый DNS Windows. Имя провайдера нельзя включить в перенаправляемый список, чтобы не создать рекурсию. При ошибке сохраняются известные bootstrap адреса. Поддерживаются только публичные bootstrap IP и HTTPS на стандартном порту.
- Код и конфигурация службы размещаются в защищённой `%ProgramFiles%\GeoRoute DNS`, состояние и ограниченный журнал службы — в `%ProgramData%\GeoRouteDNS`. Произвольные запросы и cookies не записываются. Перед обновлением сохраняется резервная копия конфигурации и собственных правил; при сбое применения выполняется откат.
- Правила и автоматическая служба сохраняются после выхода из GUI и перезагрузки Windows. SCM перезапускает службу после сбоев. Это механизм сохранения настройки, а не утверждение, что перезагрузка конкретного компьютера уже проверена.

## Ограничения и диагностика

Успешный DoH означает ответ DNS, а не открытие сайта, вход или ответ модели. NXDOMAIN показывается отдельно и не доказывает поддержку сайта. Перед включением установленная служба и системный resolver проверяются на первом выбранном сайте; при ошибке сохраняется прежняя настройка. Остальные сайты списка должны быть проверены в их приложениях.

Hosts имеют приоритет над DNS. Если выбранное имя уже задано там, применение остановится с названием конфликта. Для имеющегося рабочего ChatGPT/Gemini hosts-профиля можно добавлять другие сайты через DNS независимо. Кнопка на главной управляет основным hosts-профилем; дополнительный DNS имеет отдельный статус на главной, на странице серверов и в своём окне.

Приложения с собственным Secure DNS могут игнорировать DNS Windows: в них нужно выбрать системный DNS. VPN, корпоративные политики и ограничения сети также могут влиять на маршрут. Сертификаты для обхода ошибок не отключаются.

DNS-транспорт и отказ для невыбранных доменов проверяются настоящими локальными UDP/TCP-запросами в тестах. SCM/LocalService, перезапуск и добавление/удаление уникального тестового NRPT-пространства проверяются в одноразовом Windows runner; DNS адаптеров и hosts сверяются до/после. Это не подмена пользовательской проверки конкретного сервиса.
